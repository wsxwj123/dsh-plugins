# BRIEF — dsh-composer-tools（输入体验增强插件）

## 背景与动机

从 claude gui 移植两个"输入体验"功能到 DSH：

1. **方向键输入历史**：↑ 翻看本会话发过的输入，↓ 往回翻，翻到底恢复正在编辑的草稿。claude gui 已有实现（ChatInput.jsx），但触发门槛与用户期望不符——claude gui 单行恒放行、多行要求光标在**文本最开头/最末尾**；用户要求的是光标在**第一行/最后一行任意位置**即可触发，中间行不触发（防编辑时误翻）。
2. **指令查看 + 提示词库**：查看 DSH 实际加载的指令层级（全局 `~/.dsh/AGENTS.md` + 项目根到 cwd 每层 AGENTS.md/CLAUDE.md），并内置提示词库（复用 claude gui 的 Cherry Studio 开源预设 780 条）供浏览/搜索/复制。

两个功能合成一个插件（用户拍板），技术形态不同但共享输入框挂载点。

## 功能清单

### F1 方向键输入历史
- 输入 X：多行文本中光标在第一行（任意列）按 ↑ → 得到 Y：翻到上一条（更旧）历史，替换输入框内容，光标移到末尾
- 输入 X：多行文本中光标在最后一行（任意列）按 ↓ → 得到 Y：翻到下一条（更新）历史；已是最新一条时按 ↓ 恢复进入历史前的草稿
- 输入 X：单行文本（无换行）按 ↑/↓ → 得到 Y：直接翻历史（无论光标位置）
- 输入 X：多行文本中光标在中间行按 ↑/↓ → 得到 Y：不触发，光标正常上下移动（编辑优先）
- 输入 X：按 ←/→ → 得到 Y：永不触发，光标正常左右移动
- 输入 X：中文输入法合成期按 ↑/↓ → 得到 Y：不触发（IME 候选框选字优先）
- 输入 X：shift/cmd/ctrl/alt 按住时按 ↑/↓ → 得到 Y：不触发
- 输入 X：按 ↑ 翻到历史中 `/` 开头的条目 → 得到 Y：继续正常翻历史，不弹出斜杠命令菜单
- 输入 X：发送一条消息 → 得到 Y：内容记录进本会话历史（去重、去空白、最新在前）
- 输入 X：翻历史途中手动编辑/退格 → 得到 Y：游标重置为 -1（退出历史态，不再翻）
- 持久化：历史存 localStorage（按会话 sessionId 隔离），刷新页面/重启后仍在
- 上限：每会话 100 条，超出丢弃最旧

### F2 指令查看（输入框面板）
- 输入 X：点击输入框工具区的指令按钮 → 得到 Y：打开浮层面板（浮在输入框上方），tab 展示 DSH 实际指令层级：
  - 全局：`~/.dsh/AGENTS.md`（存在则展示）
  - 项目：项目根（`.git` 标记）到 cwd 每层目录的 `AGENTS.md` / `CLAUDE.md`（按 DSH agent-instructions 的实际发现顺序展示，含 `.local` 变体）
  - 会话：当前会话的自动记忆/上下文指令（调研结论：DSH 无会话级指令查询口子，**明确不做**，只做全局+项目两级）
- 输入 X：面板中点"重新加载" → 得到 Y：重新读文件内容（支持文件被外部修改）
- 输入 X：在面板搜索框输入关键词 → 得到 Y：**跨所有已发现指令文件全文搜索**（标题/路径/正文），命中列表展示「文件 + 所在行 + 行片段」，点结果跳到对应文件并定位到该行（文件多时不用肉眼翻）
- **可编辑（用户拍板：全局 + 项目级都可编辑保存）**：全局 `~/.dsh/AGENTS.md`、项目各层 AGENTS.md/CLAUDE.md 及其 .local 变体均可编辑并保存回文件（写操作需明确确认对话框，因会改变模型行为）
- 项目级文件写回前必须确认目标路径在项目根范围内（防路径逃逸），.local 变体随项目文件一起展示可编辑

### F3 提示词库（同一面板的第二 tab）
- 输入 X：切到"提示词库"tab → 得到 Y：展示内置 780 条提示词（复用 claude gui 的 prompt-templates.json，Cherry Studio agents-zh.json），按分类折叠浏览
- 输入 X：搜索关键词 → 得到 Y：按标题/描述/正文过滤命中条目
- 输入 X：点条目的"发送到输入框" → 得到 Y：提示词全文**追加**到输入框末尾——输入框为空则直接放入；已有内容则先补一个空行再追加（不覆盖、不丢字、不自动发送）
- 输入 X：点条目的"复制" → 得到 Y：提示词全文进剪贴板（官方 writeClipboard，失败给 UI 反馈）
- 许可：数据源自 Cherry Studio agents-zh.json（AGPL-3.0），README + 面板内标注来源与许可并附链接（用户拍板：打包+标注来源，风险自担）

## 明确不做（边界）

- ❌ 不做跨会话输入历史（历史严格按当前会话隔离）
- ❌ 不新增会话级指令文件（DSH 无此机制，不自行扩展存储）；不展示会话级指令（调研确认无查询口子）
- ❌ 不做自动记忆（auto-memory 由 DSH 自身管理）
- ❌ 不拦截左右键、不拦截 IME 合成键、不拦截修饰键组合
- ❌ 不碰斜杠命令菜单（DSH 原生 `conversation.input` 仲裁保持不动，历史导航只在自己判定放行的场景生效）
- ❌ 不做 claude gui 的"队列召回"（空输入 ↑ 召回排队消息）——DSH 队列语义不同，本插件不覆盖
- ❌ 不替换 conversation.composer.bar（等于重写整条输入链路，不值）

## 成功标准

1. F1 在真实 dsh web 环境：多行中间行按 ↑/↓ 光标正常移动、首/末行正常翻历史、单行直接翻、草稿翻到底能找回、IME 下不误触、命令菜单打开时 ↑/↓ 仍归菜单
2. F2 面板能列出并展示 DSH 实际会加载的指令文件（与 agent-instructions 发现逻辑一致），路径显示正确；全局/项目级可编辑保存，写回路径在项目根范围内
3. F3 780 条提示词可浏览/搜索/发送到输入框（追加空行分隔）/复制；来源与 AGPL-3.0 许可已标注
4. 三层测试全绿：单测（历史核心逻辑/指令发现/文本追加）+ 契约验收（严格替身模拟 cordis 访问约束）+ 真实环境 e2e（headless profile 加载）
5. 插件安装后 dsh 正常启动、无崩溃、无 console 报错，卸载干净无残留

## 项目类型与平台范围

- 类型：dsh（cordis）插件，双半结构（host 端 + client 端），复用 dsh-session-manager 的工程模式
- 平台：macOS 本机 dsh web（`@deepseek-ai/dsh@0.1.0-rc.6`）；client 端面向 Chromium 系浏览器；不做 Windows/Linux 专项适配，但代码避免平台专属 API（除剪贴板等标准 API）
- 技术栈：与 session-manager 相同（TypeScript + React client + host 端 node），pnpm workspace

## 测试策略

三层防线（AGENTS.md cordis 红线）：
1. **单测**（`tests/unit/`）：历史核心逻辑纯函数化——门槛判定（单行/首行/末行/中间行/IME/修饰键）、游标移动、草稿保存恢复、去重、上限裁剪、localStorage 读写
2. **契约验收 + 严格替身**（`tests/acceptance/`）：模拟 cordis 访问约束（核心属性放行、服务属性抛错），验证插件不裸访问未注入服务
3. **真实环境 e2e**：headless profile 真实加载插件 + 假接收端，验证启动无崩溃、DOM 注入生效

## 敏感面声明（安全审计依据）

1. **读取范围**：`~/.dsh/AGENTS.md`、项目目录树中的 AGENTS.md/CLAUDE.md 及其 .local 变体、浏览器 localStorage（仅本插件自己的 key）
2. **写入范围**：**全局 + 项目级指令文件**（用户明确确认可编辑）：`~/.dsh/AGENTS.md`、项目根内各层 AGENTS.md/CLAUDE.md/AGENTS.local.md/CLAUDE.local.md——写回前路径校验必须在项目根内（防逃逸）；**不写会话文件、不碰 trash/删除逻辑**；浏览器 localStorage（输入历史、UI 状态）
3. **密钥/登录态**：不需要
4. **外部地址**：不发起任何网络请求（提示词数据随包内置，不下载）
5. **第三方数据**：提示词库 780 条源自 Cherry Studio agents-zh.json（AGPL-3.0），打包进 MIT 插件，README+面板标注来源与许可（用户已确认接受该风险）
