# TEST-PLAN — dsh-session-manager 验收测试清单（人话版）

> 定位：给开发代理、测试员、用户看的验收清单。分两部分——
> **A 自动化**（node 侧，`node --test` 可一键跑，共 **65** 条）+ **B 人工走查**（client UI 侧，无法 headless，需在真实 DSH Web GUI 操作）。
> 依据：`.devflow/BRIEF.md` + `.devflow/INTERFACE.md`（不含实现）。
> 每一条都是"场景 / 怎么操作 / 预期看到什么"，照做即可。

## A. 自动化用例（node 侧，65 条全自动）

> 文件：`tests/acceptance/{delete,restore,emptyTrash,trash,unarchive,auth}.test.js`
> 跑法：在 `packages/dsh-session-manager` 下执行 `node --test`（自动发现 tests/）；或用
> `node --test "tests/acceptance/*.test.js"`。**全程用临时目录，绝不碰真实 ~/.dsh。**
> 实现方注意：这些测试把 node 半侧的对外行为当作"契约镜像"来校验，纯黑盒，不 import 内部实现。

### A1 `/sm/delete`（27 条）
| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| 1 | 删除普通会话 | 调 delete(带 cwd) | 200 ok:true，会话目录从原位消失、整目录（含 artifacts）进回收站 |
| 2 | 删除含附属文件的会话 | 目录里预放 local-artifact.bin 再删 | 附属文件一并整体移动 |
| 3 | 缺省 cwd 删除 | 只传 id，会话造在 sessions 根下 | 200 ok，目录被移走 |
| 4 | 普通会话不碰归档集合 | 删后查 archivedSessionIds | 集合 unchanged |
| 5 | 非法 id 一律 400 | 空串/./../含/含\\/控制字符 | HTTP 400，code=invalid-id |
| 6 | id 类型错 | 数字/对象/数组/null | 400 invalid-id |
| 7 | 中文 id | id=会话-中文-测试 | 200 ok，正常移入回收站 |
| 8 | cwd 非字符串 | cwd=42 | 400 invalid-cwd |
| 9 | title 非字符串 | title=99 | 400 invalid-title |
| 10 | title 超长 | title=256+字符 | 400 invalid-title |
| 11 | title 恰好 256 | title=256字符 | 200 ok（边界合法） |
| 12 | 缺 body | 不传 body | 400 bad-request |
| 13 | body 非法 JSON | 发 `{ id: "broken` | 400 bad-request，不动文件 |
| 14 | body 是数组/标量 | 发 `[1,2]`/`"str"`/`42` | 400 bad-request |
| 15 | 源目录不存在 | 删一个从来没见过 id | 200 ok:false session-dir-not-found，不产生回收站条目 |
| 16 | cwd 无法定位 | cwd 空串 | 200 ok:false session-dir-not-found |
| 17 | 运行中会话删除 | 先把 id 标记为 running 再删 | 200 ok:false session-running，host 拒移，目录不动 |
| 18 | 未过信任 fence | 带非本机 Host | 403，文件不动（反向护栏） |
| 19 | 越界前置（编码逃逸 id） | id 含会被编码改写的逃逸字符 | 200 ok:false path-out-of-bounds，不移动 |
| 20 | cwd 落在 sessions 外 | cwd 被映射到 sessions 根之外 | 200 ok:false path-out-of-bounds，不移动 |
| 21 | 删除归档会话（两步） | 归档集中含该 id 再删 | 200 ok，文件进回收站 + id 从归档集移除，其他归档项保留 |
| 22 | 第二步失败(partial) | 模拟归档写失败 | 200 ok:false system-error，但**文件已移走**、归档集仍含 id（中间态可重试） |
| 23 | partial 后重试 | 恢复可用再 delete 同 id | 200 ok：幂等跳第一步、补齐归档清理 |
| 24 | 重复 delete | 同一 id 删两次 | 第二次也 200 ok，无重复副作用 |
| 25 | 并发 delete 同归档 id | 同时发两请求 | 都 200 ok，最终文件在回收站、归档集只清一次 |
| 26 | 中文/空格会话目录名 | id=含空格 会话 | 200 ok，回收站路径合法 |
| 27 | 超长 title 不影响删除 | 长标题 | 200 ok（title 仅展示） |

|---|---|---|---|

### A3 `/sm/emptyTrash`（8 条）
| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| 1 | 二次确认清空 | 带 confirm:true | 200 ok，回收站根全部条目删除 |
| 2 | 清空后列表 | 清空后 /sm/trash | 清单为空 |
| 3 | **缺 confirm 一律 400** | 无 body / 空对象 / confirm=字符串 / confirm=数字 | 400 confirmation-required，**不动任何文件** |

### A6 信任 fence（8 条）
| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| 1 | 同源 loopback | 本地 Host 调任意端点 | 通过，请求可达业务 |
| 2 | **反向：非本机 Host** | Host=evil.example | 403，delete 不移动文件 |
| 3 | **反向：跨源 Sec-Fetch-Site** | cross-site | 403 |
| 4 | **反向：跨源 Origin** | Origin=https://evil.example | 403 |
| 5 | 403 优先于 confirm | 跨源 + confirm:true | 403 仍先行，不清空 |
| 6 | fence 逐请求 | 一次 403 后再想同源请求 | 同源正常，fence 不污染后续 |
| 7 | 非本机 Host 的 restore | Host=198.18.x.x | 403，条目不动 |
| 8 | 未知方法 | 调 /sm/nonexistent | 404 而非 403 |

## B. 人工走查清单（client UI 侧，在真实 DSH Web GUI）

> 无法 headless，需在装好插件（client 半）的 DSH web profile 里手工操作。浏览器为现代 Chrome/WebKit。

### B1 删除入口 & 正常删除
| # | 场景 | 怎么操作 | 预期看到 |
|---|---|---|---|
| 1 | 删除按钮出现 | 鼠标悬停任一非 blank、非运行中的会话行 | 行内出现删除（垃圾桶）按钮 |
| 2 | 点击删除立即隐藏 | 点击删除按钮 | 该会话**立即**从列表消失 |
| 3 | 撤销条出现+倒计时 | 删除后看界面 | 出现撤销条，文案含**会话标题**，显示 5 秒倒计时并递减 |
| 4 | 到点真删 | 什么都不做等 5 秒 | 会话保持隐藏；刷新页面后该会话**不再出现**（真实删除） |
| 5 | 撤销恢复原位 | 5 秒内点「撤销」 | 撤销条消失，会话**重新出现在列表原位置**；等 5 秒不消失；刷新仍在 |

### B2 撤销条韧性 & 多会话
| # | 场景 | 怎么操作 | 预期看到 |
|---|---|---|---|
| 1 | 撤销条跨视图存活 | 删一个会话→切到别的面板/视图→切回来 | 撤销条还在，剩余秒数**连续**（不重置、不倒桩） |
| 2 | 多会话并行 pending | 连续删 2+ 个会话 | 每会话一条独立撤销条、独立倒计时，可分别撤销 |
| 3 | 快速双击删除按钮 | 对同一会话快速连点两次 | 只出现**1 条**撤销条（幂等，不重复入队） |
| 4 | 倒计时中再点删除 | 等几秒后再点同一会话 | 不重复入队，撤销条仍只有一条，保持原倒计时 |

### B3 特殊状态保护
| # | 场景 | 怎么操作 | 预期看到 |
|---|---|---|---|
| 1 | 运行中会话 | 对 running 会话点删除 | 前端提示「请先结束运行中的会话」，**不发起删除** |
| 2 | blank 空会话 | 对新建空会话行悬停 | **无**删除按钮（不出现） |
| 3 | 删除当前选中会话 | 选中某会话后删除 | UI 回到 no-session 态（或自动选中相邻最近会话）；点撤销恢复后，该会话回到列表但**不再自动选中** |
| 4 | 删除后、倒计时内刷新 | 删除后立即刷新页面 | client pending 被清空；该会话**未被实际删除**，仍在列表（数据安全） |
| 5 | 撤销条文案防混淆 | 同时删标题不同的两个会话 | 每条撤销条明确该会话标题，不混淆 |

### B4 归档入口 & 视图
| # | 场景 | 怎么操作 | 预期看到 |
|---|---|---|---|
| 1 | 归档入口 | 看侧栏底部「设置」旁 | 出现「归档」按钮；窄栏可能只显图标，行为一致 |
| 2 | 归档视图列表 | 点「归档」 | 展开归档会话列表，每行显示标题可识别身份 |
| 3 | 只有归档会话可见 | 对比正常列表 | 归档过的会话**只**在归档视图出现，不在正常列表 |

| 5 | dangling 不显示幽灵行 | 归档集含一个"byId 已不存在"的 id | 该行被隐藏，不显示幽灵行、不崩溃 |

### B5 归档操作
| # | 场景 | 怎么操作 | 预期看到 |

| 5 | 归档删除-撤销 | 归档删除后 5 秒内点撤销 | 行回归档视图 |

## C. 覆盖说明 & 未覆盖（诚实清单）
- **覆盖度**：正常路径(BRIEF 每条 F1/F2/F3 主路径)、边界(空/单元素/非法 id/回收站空/多条目/路径空格)、错误路径(乱输入/缺参/类型错/越权 403/缺 confirm 400/文件缺失/依赖不可用/越界)、反向断言、幂等/并发、用户没想到(中文/空格目录名、5 秒边界、多会话并行)。
- **未覆盖 & 原因**：
  1. **5 秒倒计时计时行为本身**（从 10 精确递减到 0、撤销条消失的精确时机）——纯 client 计时器，node 侧无法 headless，归入 B2/B7 人工走查。
  2. **UI 视觉/交互细节**（悬停出现按钮的像素、撤销条样式、窄栏 rail 态图标）——client React 层，人工走查 B1/B4。
  3. **真实 DSH host 的 storageDomain / SessionStore 集成**——harness 用临时目录模拟这些依赖形状；真实域写入行为需在装有 node 半的 DSH 里人工/集成验证。**注意：这是最大设计风险，node 半的真实 storageDomain 写入路径不完全等于本测试夹具，实装时建议补一轮 node 半真机冒烟。**
  4. **归档（archiveSession）官方入口→归档视图联动**——官方入口非本插件新增，联动归人工走查 B4。
  5. **系统资源级故障**（磁盘满、并发极高、进程 kill 中途）——不在本批次，留待发布前冒烟。
  6. **cordis 注入约束的自动化**（未 inject 服务裸访问抛错、ctx.get 可选读）——node 半的 cordis 集成环境依赖真实 dsh 运行时，无法在临时目录夹具里自动化；归 B8 人工走查 + 开发期 T6 联调第一步（装包→重启→Console 无报错）。教训：LRN-20260814-01 dsh-pet-bridge 启动崩溃，测试替身模拟 cordis 约束是开发代理自测要求（见 PLAN §9.4）。
