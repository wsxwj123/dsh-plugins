# 真机 UI 实测清单（桌面版 0.2，卡点③）

给柚子：下面 6 条只能在桌面版 App 里点，自动化跑不了（宿主进程由 App 管理，没有可供 Playwright 连的 web 端口）。
每条都写了「怎么点」和「应该看到什么」。**看到什么就报什么，不符合也照实说**，我据此决定是否打回开发。

## 第 0 步（我做，你先别动）

桌面 profile 现在链的是**主 clone 的旧代码**（`~/Desktop/app/dsh-plugins/packages/...`），不是带修复的工作区。所以在你测之前，我会把这两个包重新指向工作区：

```bash
dsh plugin --profile desktop add dsh-composer-tools@link:$HOME/Desktop/app/dsh-plugins-wt-0.2/packages/dsh-composer-tools
dsh plugin --profile desktop add dsh-appearance-gallery@link:$HOME/Desktop/app/dsh-plugins-wt-0.2/packages/dsh-appearance-gallery
```

然后你需要 **⌘Q 完全退出并重开桌面版**（热重载会让正在跑的会话掉工具面，这是已知现象）。

---

## B5（首验项，最重要，先做这条）

**为什么先做它**：修复的核心假设是「0.2 会给插件下发 `sessionId`」，这一点只有真机能证。它不过，B2/B3 也没有意义。

1. 打开一个**绑定到具体目录**的旧会话（比如工作区是 `~/Desktop/claude/...` 的那些），点开「指令 / 提示词」面板 → 记下它显示什么
2. 切到**另一个不同目录**的会话，再点开面板 → 记下显示什么
3. 判定：**两次显示的工作目录不一样 = 通过**（说明 `sessionId` 真的跟着会话切换走）；两次都一样、或都显示「无当前会话目录」= 不通过

## B2

绑定目录的会话里点开面板 → 应该显示**该会话的工作目录**，而不是「无当前会话目录」。

## B3

在同一个面板里看指令列表 → 应该出现 **`~/.dsh/AGENTS.md`（标为 global）**；点它 → 编辑器里能看到你那份 105 行的内容。

## B4

新建一个**空白会话**（未选目录），点开面板 → 应该显示空/无目录状态，**不报错、不崩溃**。

## C3

设置 → 通用 → 应该能看到**外观（皮肤）入口**。

## C4（功能闭环，5 小步）

在皮肤面板里依次试：① 切一个主题 ② 切一个皮肤 ③ 试穿后回滚 ④ 导入并应用 ⑤ 恢复默认。
判定：5 步都生效，且事后页面里**没有残留**的 `<style data-plugin>` 标签与 `data-dsh-*` body 属性（可在开发者工具里看）。
